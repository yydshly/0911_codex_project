我们的理解 / 多 Agent 工具

Munder Difflin

管理多个已有 Agent，通过文件实现协作通信。

配置身份、模型和任务，集中查看运行状态。Agent 将消息写入本地收发箱，平台负责投递和适时唤醒，Agent 再读取文件、执行工作并回复。

能力与部分源码已核对；上游运行未实测。此页是中文研究展示，不提供在线 Agent 服务。暂不归档，后期按需深入。

02 / 交互机制

文件不会自行唤醒模型，平台把消息变成下一轮输入

以“Agent A 请 Agent B 检查代码”为例。选择步骤查看职责与数据流，以下为固定教学说明。

执行者：Agent A

把请求写入自己的发件箱

A 将收件人、请求类型、主题与正文写成 JSON，保存到自己的 outbox。此时消息已经落盘，B 还没有因此开始工作。

agents/A/outbox/消息.json

当前 Stop 处理已取消“未读消息强制续跑”的旧路径，改为空闲时机投递输入。约 1.5 秒、4 秒、15 秒分别是相关检查间隔，不是送达时延承诺。
