# 产品验证推进循环

执行技能：marketing-loops 1.2.0；输入：04-validation.md、人工核验后的 feedback.json；参考：loop-template.md、loop-state.md。此为本地新增的手动执行器，采用原技能九项结构；不是上游自带软件，也没有建立定时任务。

| 组件 | 本次定义 |
| --- | --- |
| 检查节奏 | 负责人补入真实反馈后手动运行；建议每周复盘一次，未创建日程 |
| 行动触发 | 存在未处理且字段合格的新反馈；同一文件不变则跳过 |
| 目的 | 把真实尝试的结果转为一个待负责人审阅的下一步 |
| 使用技能 | product-marketing 维护背景；analytics 定义口径；本循环不自动调用模型 |
| 循环体 | 校验输入 → 核对已处理 ID → 按结果生成建议 → 保存状态与日志 |
| 自检 | 有证据说明、无重复 ID、状态值有效；completed 仅为用户自报，建议先人工核验 |
| 状态与幂等 | .agents/loops/product-validation.json 保存 handled、输入哈希、次数；同 ID 内容变化拒绝，避免静默改写历史 |
| 停止与退出 | feedback.json 中 enabled=false 时停止；无新增时不产新建议；格式错误直接退出且不修改状态；无网络、无对外行动 |
| 输出 | next-actions.md 待审建议、持久状态和追加日志；不自动更改产品定位、不发送信息 |

首次运行：只建立当前记录的基线，不把历史反馈当成新信号。当前 records 为空，因此没有客户结论。后续新增 completed → 先核验结果再询问下一真实任务；blocked → 收集最小失败材料，判断引导/环境/能力缺口；abandoned → 了解放弃原因，重新确认任务价值。建议采用预设规则，不能替代客户研究或模型分析。

运行方式（仓库根目录）：`node projects/010-marketingskills/app/scripts/run-product-loop.cjs`。只处理本场景目录；可传入测试目录用于隔离验证。每次记录检查数、行动数与结果，同一次输入不会重复生成建议。串行手动运行，尚未支持多进程并发调度。
