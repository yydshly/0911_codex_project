## 一、能力与场景

上游将专业营销知识组织成 50 个技能，用于回答“为谁提供什么价值”“怎样表达与传播”“怎样减少使用阻力”“如何用数据验证”。适合有产品、内容或客户资料，但缺少完整营销方法的技术团队。

| 本地分类 | 主要工作 | 代表技能 |
| --- | --- | --- |
| 定位与决策 | 产品背景、用户研究、计划与定价 | product-marketing / customer-research / marketing-plan |
| 内容与创作 | 内容规划、文案、编辑与媒体指导 | copywriting / copy-editing / image / video |
| 搜索与发现 | SEO、AI 搜索可见性、页面与站点结构 | seo-audit / ai-seo / programmatic-seo |
| 页面与转化 | 表单、注册、首次使用与付费入口 | cro / signup / onboarding |
| 传播与推广 | 广告、发布、活动与联合传播 | ads / launch / social |
| 销售与客户关系 | 潜客、邮件、销售资料与运营 | prospecting / emails / revops |
| 留存与增长 | 流失预防、推荐、社区与免费工具 | churn-prevention / referrals / free-tools |
| 衡量与实验 | 事件、归因和实验设计 | analytics / attribution / ab-testing |

完整名称、版本及来源路径保存于 [inventory.json](sources/inventory.json)，页面每个技能链接固定提交。分类恰好覆盖 50 个技能，不重复计数。工具统计为 `tools/clis/*.js` 64 个与 `tools/integrations/*.md` 95 份，不相加为“已连接平台数量”。上游部分说明中的旧计数不作为本研究统计依据。

典型场景：

- 独立开发者发布：产品背景 → 发布计划 → 官网文案 → 渠道材料 → 使用反馈，需要真实能力与演示。
- 注册转化改善：核对事件 → 找出阻力 → 形成假设 → 实验 → 解释结果，需要正确埋点和足够样本。
- 技术知识站：内容结构 → 文案 → 导航 → 阅读反馈；目标可以是找到案例和理解内容，不必套用付费转化。
- 营销咨询：每个客户维护独立背景，将预算、团队能力与渠道计划放进统一工作文档。

这些是依据技能设计推导的应用方式，不是已复现的成功案例。无业务数据时可以形成草稿和假设，不能生成真实效果结论。

## 二、技术原理

### 1. 技能发现与按需加载

`SKILL.md` 由 YAML 头部和 Markdown 正文组成。`name` 标识技能，`description` 说明任务、触发词与相关技能边界。宿主先发现描述，在需要时读取全文；详细框架、示例和模板放在 `references/`。

这是 [Agent Skills 规范](https://agentskills.io/specification) 的组织方式。选择与遵循指令依赖宿主 Agent。上游没有提供独立训练出的营销模型，也不以向量数据库或微调为核心依赖。文档中的要求并非由程序强制执行的规则。

### 2. 产品背景是共享上下文

`product-marketing` 可根据代码、README、页面和现有资料起草 `.agents/product-marketing.md`，再补充核对缺失信息。内容包括产品概览、受众、痛点、竞争差异、切换阻力、用户用语、品牌、证据和目标。其他代表性技能要求先读取该文件，再询问任务特有的信息。

背景文档维护版本与变更记录，并兼容旧路径。它减少重复解释与渠道之间的表达漂移，但属于需要维护的共享文件，不是自动同步数据库、自动用户研究或无限记忆。

### 3. 把专业判断展开为步骤

`cro` 先确认页面类型、主要行动和流量背景，再分析价值表达、标题、行动入口、视觉层级、信任证据、用户疑虑和操作阻力。输出为小改动、优先项目、实验想法与文案备选。

技能以文字引用衔接，例如 `cro` 指向 `copywriting` 与 `ab-testing`。引用说明工作分工，不代表已经自动启动多个代理或强制依序调度。

### 4. 业务执行依赖工具

`tools/REGISTRY.md` 为能力和接入方式索引，`tools/integrations/` 提供平台说明，`tools/clis/` 含实际 Node.js 请求脚本。MCP、API、CLI、SDK 是不同接入路径；有文档不表示已经连接服务。

抽查 `ga4.js`：读取 `GA4_ACCESS_TOKEN` → 解析参数 → 构造 Data / Admin / Measurement Protocol 请求 → 通过 `fetch` 请求 → 返回 JSON 或状态与正文。`--dry-run` 返回请求预览并遮盖认证字段，不实际发送该请求。

凭据存在性检查在主逻辑之前，所以预览也需要满足该检查。本次进一步使用虚拟凭据，在阻断网络的 VM 环境中运行原样上游脚本，验证报表、转化创建、事件发送三个预览路径：没有发出 fetch 调用，输出认证字段已遮盖，请求结构符合这些源码分支。未调用真实 GA4，不能声明平台接口兼容、完整认证和所有错误分支已经验证。安装技能后是否可访问工具目录也需单独确认。

### 5. 长任务通过文档约定续接

`marketing-plan` 规定 INIT（调研）→ REVIEW（逐节确认）→ FINALIZE（汇总与验证），通过 `progress.md` 记录进度，最终生成 `final_plan.md`。Agent 读取文件后继续先前步骤。

这与独立执行框架不同：阶段要求仍需 Agent 遵循，不能推断存在独立调度、后台长期运行或强制的结果验收服务。

### 6. 持续循环的状态与停止条件

进一步阅读 `marketing-loops` 后，可确认上游提供的不仅是增长想法：固定版本说明了 43 个循环方法，并要求每项定义检查频率、行动条件、目的、技能、步骤、自检、状态与幂等、停止条件和输出。相关参考文件包含循环目录、模板、编排、状态和检查点。

检查频率与行动频率要分开：定期查数据不表示每次都要行动；保存去重键、上轮标记、冷却期和已处理集合，才能减少重复工作。错误、证据不足、范围变化或停止标志出现时，循环需要跳过、停止或交由人处理。

调度仍依赖宿主或外部系统。技能可以指导配置循环，却不意味着安装后已有后台定时服务。这里没有创建任何实际自动化。本地第六个教学场景演示这种“检查 → 自检 → 按条件行动 → 保存状态 → 停止或续接”的逻辑。

### 7. 与其他实现方式的关系

| 方式 | 能借鉴什么 | 本库的实际关系 |
| --- | --- | --- |
| 一次性提示词 | 为单项任务提供要求 | 技能把要求模块化并附加版本、资料与相关工作入口 |
| 知识检索系统 | 查找外部或私有资料 | 互补能力；本库核心读取文档，不要求向量数据库 |
| 工作流与执行框架 | 明确调度、状态与失败恢复 | 技能可提供节点方法，但需要另外实现运行与验收 |
| 完整营销平台 | 账户、素材、渠道和数据管理 | 工具指南可连接部分服务；本库没有一个统一运营后台 |

以上为本地架构分析，不是性能或优劣评测。

## 三、对我们的意义与扩展

1. **帮助读者使用研究成果**：把原库能力表达为读者可完成的任务，使用源码和演示作证，不添加未经验证的效果数字。
2. **研究方法技能化**：将能力分析、上下游对照、来源记录、演示核验整理成触发条件、步骤、产物与检查要求。
3. **探索持续执行协作**：本库提供业务方法，LongHorizon-Harness 研究提供持续推进视角，工程案例库提供技术经验；尚未实现集成。

| 优先级 | 扩展 | 可检查的产物 |
| --- | --- | --- |
| 高 | 中文与技术读者适配 | 中文术语、受众背景和本地案例 |
| 高 | 事实与证据约束 | 声明关联源码或演示；事实、假设、建议分别记录 |
| 高 | 技能效果评测 | 固定任务对比准确性、覆盖度、修改成本和可执行性 |
| 中 | 多项目上下文 | 项目独立背景，共用总仓库风格与证据标准 |
| 中 | 数据反馈 | 定义有用事件，把真实结果写回下一轮分析 |
| 中 | 与执行框架衔接 | 输入、产物、验收标准、失败处理与恢复记录 |

先选工程案例手册试点：明确读者任务、改善一个入口、检查事实和链接，观察能否找到合适案例。流量不足时用任务式阅读测试，不把少量点击变化解读为显著提升。

## 四、本地展示与验证

网页采用原生 HTML / CSS / JavaScript，没有远程运行依赖。`content.js` 与 `more-scenarios.js` 保存八类映射和六个六步场景；`catalog.js` 保存 50 个技能的中文详细卡；`inventory.js` 保存版本；`evidence.js` 保存源码入口、95 份指南和 64 个脚本信息。`app.js` 提供分类、技能详情与协作跳转、场景和步骤导航，使用文本节点呈现内容。

`app/handbook.html` 为上手、工程结构、工具、选型、指标、成本与实践章节的源，`build-handbook.cjs` 同步网页片段和 [50 技能中文手册](catalog.md)。生成手册包含全部工具指南和脚本目录，可离线阅读。中文输入、方法、产物是本地源码归纳；验收与协作顺序为实践建议，不是强制的上游运行契约。

本页无后台、账户、真实采集、投放、发信、定时任务或模型调用；所有示例输出预先编写。PNG / SVG 为原创功能关系图，没有模拟软件截图。

检查结果见 [verification.json](verification.json)：50 个技能详情和关系完整、来源与生成手册一致、95/64 项目录、六场景引用及导航逻辑、静态资源和文档链接，以及三个上游 GA4 离线预览路径。原理 PNG 已目视检查。没有进行浏览器视觉或交互验收，没有测试真实营销效果。

## 五、质量与适用范围

- 上游包含英美 SaaS、广告、邮件等语境中的经验与判断。中文和其他行业应调整输入、例子与衡量，不能只翻译名称。
- 文案、SEO 与策略中出现的效果数字属于上游论述，未在本地重复验证。本地展示不把这些数字当作效果保证，也不盲目照搬具体平台规格。
- 归因模型分配贡献，并不等于测出了因果增量；点击、注册、激活、留存和收入要分别定义。
- 50 个文件都具备完整中文阅读卡，不表示 50 个技能都已完成端到端实测。结构校验和离线预览检查也不是业务质量评测。
- MIT 许可不覆盖外部模型和平台的免费使用。实际成本包括模型、数据服务、媒体生成、渠道操作、维护与人工审阅，不在无真实输入时计算虚假收益。
- 工具登记存在赞助伙伴和作者工具的披露规则。标记用于说明来源关系，不能等同于最佳选择；本地保留上游标记及出处。

建议评测：对同一个入口优化任务，固定输入与版本，对比基础任务提示和技能辅助结果的事实准确性、遗漏、人工修改成本和可执行性；有真实流量后再评估适当业务指标。评测方案尚未在实际产品上运行。

此处是早期“页面仅含教学展示、营销文档执行待验证”状态的更新。原六个教学场景仍是说明性文本；新增场景的五份文档工作已真实执行，定位有效性与外部需求仍待验证。
