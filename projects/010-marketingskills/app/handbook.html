04 / 从理解到使用

先准备背景，再完成一个小任务。

以下是阅读与实践路线。本页仅展示命令和方法，没有安装技能或修改宿主配置。

第一次了解

先看能力地图与一条任务流程，再看技术原理。重点理解：谁负责判断，谁操作工具，结果怎样验证。

准备实际使用

先选一个可完成的小任务，准备真实资料，再读相关技能详情与上手方法。缺少数据时先产出有依据的草稿。

准备二次开发

重点看文件结构、工具接入、阶段续接和状态去重；先定义产物及评测任务，再考虑自动化。

  1. 选一个目标。 例如改善一个案例入口，而不是一开始要求“自动做好全部营销”。明确现有页面、目标读者和期望行动。
  2. 准备共享资料。 产品做什么、为谁服务、有哪些真实证据、哪些尚不清楚。已有资料可以先起草，未知内容保留待确认。
  3. 让宿主发现技能。 检查安装位置与宿主支持情况。显式指定技能或提出清晰任务后，确认 Agent 实际读取了相关文件。
  4. 从一个产物开始。 获得可审查的诊断、文案或实验计划；保留输入、版本、来源和重要推断。
  5. 接入必要工具。 如果任务需要实际改页面、读取报表或生成媒体，再核对对应工具、环境与权限。
  6. 验证后再复用。 检查事实与完成条件，记录效果及人工修订，逐步扩大到多技能流程。

持续循环：43 个方法规格如何交给宿主运行？

marketing-loops 的固定版本说明了 43 个循环，并定义九个组成：检查频率、行动条件、目的、技能、步骤、自检、状态与幂等、停止条件、输出。循环正文可复用，实际定时、唤醒和运行仍由宿主或外部调度器提供。

定时检查核验信号按条件行动或跳过保存状态停止或等待下一轮

检查频率与行动频率分开。 某项工作可以每天检查，但只在新信号且冷却期结束时采取行动。状态文件要记住已处理项；失败时有停止与恢复办法，避免重复生成草稿或重复联系。

范围需要提前定义。 内部分析、草稿、对外发布与花费预算具有不同执行条件。上游规定明确检查点与停止开关，实际运行遵循用户授权及环境能力。本页面没有创建任何循环或定时任务。循环方法原文 ↗

为什么称为“专业方法的工程化”？

普通提示词也能提供任务指导；此库把指导组织成可发现的模块，附带版本、参考资料、共同产品背景和工具接入说明。由此更容易复用、更新与检查。但封装不会让经验规则变成确定算法：任务理解、事实质量、工具状态和验收仍影响结果。

对本地扩展，建议采用“适用任务 → 必要输入 → 分析步骤 → 证据要求 → 产物格式 → 检查方法”的结构，并保存能重复执行的评测任务。这是我们的工程建议。

06 / 外部工具如何接入

知道接哪里，也核对实际接通了什么。

95 份指南和 64 个脚本覆盖不同层次，不能相加为已连接平台数量。下列目录由固定源码提取。

API / SDK

通过 HTTP 接口或平台开发库执行操作。需要账户、认证、接口版本和请求参数；真实能力由具体服务决定。

MCP

把服务操作提供给支持该协议的 Agent。需要另外配置服务器和认证；指南中的 MCP 标记是上游登记。

CLI 脚本

本库的一部分工具是独立 Node.js 文件。它们包装请求并输出 JSON；不能替代账户授权或完整平台客户端。

实例拆解：GA4 查询请求的生命周期
  1. 读取 GA4_ACCESS_TOKEN，没有该变量时脚本退出。
  2. 解析 reports run、property、日期、维度与指标等参数。
  3. 构造 Data API 请求；预览分支只返回经过遮盖的请求信息。
  4. 实际执行时使用 fetch，将响应解析为 JSON 或状态与正文。
  5. Agent 根据数据解释结果；还要核对时间范围、指标口径、样本和错误。

本次对三个预览路径做了离线检查：报表查询、转化创建和事件发送。使用虚拟凭据并阻断网络，验证没有调用 fetch，虚拟凭据值没有出现在预览结果中。不是实际 GA4 连接测试。

数据请求失败、认证失效、限流和重复写入的处理要按脚本逐项检查。不能因为一个示例支持预览就认为所有脚本都具备相同可靠性。GA4 源码 ↗

阶段真正想知道可观察证据常见误读

常见术语，用任务理解
ICP / 理想客户画像
最适合当前产品的目标人群与资格条件。
JTBD / 用户要完成的任务
用户在具体情境下想获得的结果，包含功能、情绪或社会层面。
CRO / 转化优化
减少用户完成主要行动的阻力；行动可以是找到案例，而不一定是购买。
CTA / 行动入口
页面希望读者采取的下一步，例如打开演示或开始试用。
AARRR
获客、激活、留存、推荐、收入，用于组织增长工作的阶段。
归因 / 增量
归因按方法分配贡献；增量关注没有这项投入时结果会如何变化，两者不能混为一谈。
护栏指标
改进主要指标时也不能损害的表现，例如质量、投诉或后续留存。
幂等 / 冷却期
同一件事重复检查时不重复处理；在一段时间内避免重复行动。

证据与评测

每条声明记录来源、日期、范围与置信度。用相同任务比较基础提示和技能辅助的结果，记录失败与人工修改。

执行与状态

为多项目隔离产品背景与任务状态，定义去重、失败恢复和验收。接入持续执行框架前，先确定可检查的输入与输出。

能否替代团队？成本从哪里来？

适合用来增强小团队的研究、产出和检查能力。产品事实、客户访问、方向决策、工具配置以及业务责任仍需有人承担。上游的效率宣传不等于在本地得到验证的人员替代结论。

MIT 许可覆盖这份库，不意味着模型或外部平台免费。实际投入包括模型调用、营销数据服务、媒体生成、投放或发送、部署维护和人工审阅。评估单个流程的完成成本与错误代价，比只看技能数量更有用。

流量少时可以做任务式用户观察；样本充分时才使用适当的实验分析。不要用没有数据的统计表格制造“已经验证”的感觉。
