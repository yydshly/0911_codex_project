## 能力是什么

这是针对已有 JPG / JPEG / PNG / WebP 人像的编辑技能。它将布光、曝光、色彩、成像响应和皮肤表现分开控制，要求保留原人物的几何、自然不对称、表情、姿势和构图。

| 范围 | 允许调整 | 默认保留 |
| :--- | :--- | :--- |
| texture-only | 微纹理与皮肤反射表现 | 光照、曝光、颜色、背景、焦点与景深 |
| tone-and-exposure | 曝光、光色、调色 | 光源方向、人物与场景结构、原视角 |
| relight-and-skin | 请求的布光、曝光、肤质与氛围 | 人物身份、结构、焦点、景深、构图 |
| capture-style | 调色和成像响应，及必需的曝光行为 | 机位、透视、裁切、焦点与景深 |
| optical-restyle | 用户明确要求的视角、透视或景深变化 | 人物五官几何与其他未授权部分 |

保留要求是编辑目标，不能视作后端能力保证。

## 技术原理是什么

我们的理解：原库把摄影师对光源位置、方向、面积、软硬、颜色、强弱和阴影投射的描述整理为提示词，再把原图与这些描述交给支持图像编辑的大模型。模型负责产生最终像素，技能负责表达目标、限定允许变化的范围并组织验收。它不自研生成模型，也不通过光线追踪精确求解场景。

例如夕阳方案要求侧后方暖光、头发肩部轮廓光、自然暗侧和不加正面补光。实际结果出现了轮廓光，但正面仍亮，说明“提示词提出约束”与“模型满足约束”必须分开判断。效果图与逐字提示词见[实际调用记录](assets/experiments/README.md)。

### 规则与配方

Agent 先确定 Scope，再选择 L（主光）、E（曝光）、S（皮肤细节尺度）、P（肤质与反光）、T（光色）、G（调色）、D（成像响应）和 A（至多一种氛围）。它把“电影感”“胶片感”等描述翻译为可观察的光照、影调和成像行为。

`references/prompt-recipes.md` 是给 Agent 使用的文档，不是可执行编译器。核心为 EDIT、LIGHT、SKIN、AVOID 四行；G 或 D 改变时增加 RENDER。通常 55—110 个英文单词，复合编辑上限 135；给模型的是效果描述，不直接发送配方代码。

### 宿主图像模型

技能发现宿主已有的图像编辑能力，传入原图与提示词。仓库本身不包含模型权重、训练代码、深度／法线预测网络或物理光照求解器。光照一致性由摄影约束指导模型生成，不是经过物理计算的硬保证。

### 检查工具的实际职责

| 文件 | 实际职责 | 不能因此证明 |
| :--- | :--- | :--- |
| `check_aspect_ratio.py` | 宽高比相对差，默认允许 5% | 构图、人物或像素完全不变 |
| `evaluate_backend_gate.py` | 根据登记能力选择严格局部或尽力编辑路径 | 后端必然兑现声明 |
| `validate_edit_plan.py` | 校验计划、区域与保护信息 | 编辑必然成功 |
| `audit_pixel_regions.py` | 比较同尺寸图像指定区域的像素 | 摄影质量或光照物理正确性 |
| `validate_result_assessment.py` | 必需验收项、结论及证据路径存在 | 自动识别了人物、肤质或光影 |

当前 `backend-capabilities.json` 仅登记 `host-native-imagegen`，分类 `full-frame-generative`，不具备 `edit_mask`、`frozen_pixel_passthrough`、`exact_canvas`。严格局部编辑有契约和检查路径，但没有随库提供满足全部要求的已登记后端。

## 使用场景与限制

适合探索头像、创意人像、摄影沟通、AI 人像后处理，以及不同曝光和成像风格的教学。以上为依据能力推导的场景，尚未进行商业效果验证。

- 人物、文字、饰品与场景保持依赖具体模型和输入。
- 面部高度小于 256 像素时，规则取消新增表面微细节目标；这是上游策略，非本地验证的最优阈值。
- 肤质恢复指生成视觉合理的细节，不表示找回原图丢失的真实信息。
- 设备模拟是类别级可见特征，不等于精确复现某品牌相机或胶片。
- 上游示例缺少统一后端、重复次数、成本和失败统计，不能据此推算成功率。

## 对我们的意义

本地判断：它补充“专业任务技能”这一研究层。工程文章库整理经验，LongHorizon 管理长任务推进，OMP 提供编程 Agent 执行工具；XXG 展示摄影经验如何进入修改范围、提示词和验收标准。

可迁移结构为“最小修改范围 → 专业配方 → 可观察结果 → 独立验收”。应用到其他领域前，需要重定义输入、不变条件、工具能力与证据。

## 可扩展方向（本地建议）

1. **对照评测**：相同后端和调用预算下，比较普通要求、直接配方与完整技能。用 10—20 张代表性图片覆盖距离、肤色、光照、眼镜、多人和复杂背景。
2. **独立验收**：结合关键点、人物相似度、文字识别、构图与人工盲评，统计目标达成、身份保持、自然度、耗时、成本和失败类型。算法分数不能替代全部视觉判断。
3. **局部编辑**：接入实际支持蒙版、像素保留、固定画布的工具，再运行严格检查。
4. **批量一致性**：评测通过后维护共享风格、每图曝光差异，以及可回溯的模型和配方版本。
5. **任务调度**：用长期任务系统组织选片、编辑、验收和归档，避免把生成完成等同于结果合格。

以上不是上游已实现的能力。

## 2026-09-10 · 三次真实调用实验

使用内置 ImageGen 先生成一张合成成年人像，再将同一输入分别送入窗光、夕阳逆光和双色霓虹编辑。每种方案一次调用，没有重试筛选。全部图像原样保存为 1254 × 1254 PNG；输入与输出未经过本地后期处理。提示词采用上游 V2.1 配方思路的本地整理版本，没有自动执行上游完整技能。

| 实验 | 可见变化 | 未达标或不确定项 |
| :--- | :--- | :--- |
| 柔和窗光 | 面部和衣服稍亮、肤色较暖，整体变化较小 | 缺乏可清楚辨认的连续窗影，不能认定氛围目标达标 |
| 夕阳逆光 | 头发、肩部出现暖色轮廓光，窗外与墙面变暖，有光晕 | 正面仍较亮，无法确认完全遵守无正面补光；窗外近白，亮部形状保留有限 |
| 双色霓虹 | 左侧品红、右侧青蓝的轮廓光和背景色变化明显 | 面部主体仍由较亮的中性光照亮，品红主光和低调曝光未充分实现 |

上述是 Agent 的视觉观察，未经人工复核，也没有自动身份认证或物理光照测量。大致人物轮廓和场景布局相似不等于像素或身份严格不变。三个单次样本只能说明这些提示在当前工具上的具体输出，不能量化技能相较普通提示词的提升。

实际提示词、输入哈希、输出哈希、调用时间、工具证据与观察见[实验说明](assets/experiments/README.md)及[完整记录](assets/experiments/runs.json)。工具未公开可验证的底层模型版本、随机种子与费用，均不推测。
