# 从人像光影技能到照片产品

[返回项目](README.md) · [原库研究](notes.md) · [扩展实验与来源](assets/extensions/README.md)

## 我们扩展的是什么

借鉴原库“专业规则 → 明确修改范围 → 模型执行 → 结果验收”的结构，把摄影经验组织为用户可选择、可比较、可撤销的任务。以下为本地产品设想与实验，不是原库原有能力，也不是已经上线的照片处理产品。

实际修改仍依赖图像编辑模型。规则能表达意图，但不能创造模型没有的能力，也不能保证所有人物、商品或画面细节完全不变。

## 婚纱照的“修复”需要分清

- 曝光、白平衡、噪点等通常可以先考虑传统图像处理，便于保留原始内容。本次婚纱样例仍使用生成式模型，仅测试该路径，未集成传统处理引擎。
- 自然肤质或重新布光需要特别保护两个人的特征与受光关系；本次婚纱样例只要求曝光／偏色修正，不进行换脸、换婚纱或重建姿势。
- 划痕和背景小块缺失可以限定损伤区域修补；实际像素保留必须由支持该能力的工具及检查证明，不能仅凭提示词保证。
- 严重缺失的脸部和细节只能生成合理猜测，不能声称找回真实记忆。更多家庭参考照片可能帮助约束，也不能替代真实原片。

**老照片（未完成）：** 计划生成黑白双人照片，模拟褪色、灰尘、细划痕和一处背景乳剂缺损。要求保守修复，保持单色、软焦、颗粒、年龄和服装。输入生成两次均因网络失败未出图，没有执行修复编辑；不能声称已验证此能力。即使完成这项设计，也没有对应无损原片，不能证明历史细节被准确恢复。

**职业头像方向（复用既有参考）：** 页面再次引用此前窗光人像的输入输出及实际提示词，没有新增调用。仅作为自然布光步骤的参考；原图为休闲衣着半身人像，未验证职业照着装、构图、背景或真实身份保持。

本次新增一个成功商品输入／输出对。每个新输入单独生成，不按效果重试挑选。旧照输入与婚纱编辑各重试一次，仍均为网络失败，没有旧照输入或婚纱编辑输出；全部尝试单独记录。输出原文件、输入提示词、编辑提示词、时间、哈希与逐项观察保存在[调用记录](assets/extensions/runs.json)。没有本地后期处理。

## 产品化还需要什么

建议流程：诊断问题 → 限定修改范围 → 选择传统处理或生成式工具 → 对照检查 → 用户逐项接受／撤销。

目前尚未实现上传、区域标记、非破坏编辑历史、传统修图、严格蒙版保护、人脸／文字自动检查或批量任务。网页只展示保存好的实验。下一步应使用用户授权的实拍照片，按任务类型设计对照组与多次重复测试，并记录失败率、成本和人工复核结果。
