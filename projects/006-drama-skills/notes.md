## 技术原理

### 专业知识与执行工具分工

每个技能用 `SKILL.md` 描述入口、直接输入、步骤、责任和完成条件；参考资料提供题材、镜头、对白、连续性等知识；Python 脚本检查能客观证明的事项，执行索引、生产和导出。Agent 与模型完成理解、创作和语义判断。

本库的主要资产是行业方法与执行约束，没有提供新的基础模型。职责划分不代表每阶段必然同时运行独立 Agent。长篇分析允许在宿主支持时分批使用子代理，也可以串行执行。

### 用文件保存当前事实

单集核心创作文件是 `剧本.md`、`视觉设定.md`、`分镜.md`、`图片提示词.md`、`视频提示词.md`。场景、镜头、提示词使用稳定 ID 引用，当前文件作为下游输入，减少对旧聊天草稿的依赖。

项目不只有五个文件：配置、开发分析、审查、生产记录与后期剪辑单另有用途。各阶段只修改自己负责的内容，发现上游问题应交回对应阶段修订。

### 长材料分段与可追溯分析

原著工具先建立章节索引，检查标题单位、编号跳跃、重复和源文件变化。抽样快评、逐章提取、聚合及分集候选复用同一索引；覆盖率与进度文件帮助发现缺章和断点续做。脚本负责精确索引，大模型负责戏剧功能判断。

这降低了整本书一次进入上下文时的遗漏风险，但抽样判断仅适用于采样范围，不能冒充全量分析。

### 连续性约束与两类检查

分镜记录动作起点、主要状态变化和终点，下一镜继承可信状态；冻结关键帧只画起点。真实参考图使用 `REF-...`，外部准备图片的挂图计划使用 `PLAN-...`，图片提示词使用 `IMG-...`，避免混淆“写好了要求”和“已有真实输入”。

结构检查处理 ID、引用、显式文字约束和时间算术；语义审查处理剧情、动作落实、观众知情时机与连续性。文本约束不是生成模型的硬控制，输出画面仍需观看验证。

### 受控媒体生产

`production_tool.py` 实现准备与预览、确认、运行、状态查询和审计。执行时核对任务指纹与一次性确认，固定输入快照，再通过 JSON 标准输入调用适配器，将实际结果写回项目。

适配器使用项目外配置，凭据由运行环境提供。任务或输入变化需要重新确认；失败后再次提交不能直接复用已消费确认。源码还包含保存供应商任务标识及收取已有任务结果的机制，降低中断后重复提交风险。

适配代码包含 GPT Image 2、Seedance、MiniMax H3 视频与 MiniMax Music 路径；这些名称表示该版本实现，不代表所有账号、区域或未来接口可用。TTS 有通用生产接口，不能据此宣称内置了通用可用配音后端。

### 本地创作台与剪辑

创作台使用 Python 标准库服务与原生 HTML/CSS/JavaScript，提供浏览和编辑，保存不会直接生产媒体。剪辑工具根据已有素材及 `剪辑单.md` 调用 FFmpeg/FFprobe，检查区间、引用和字幕，处理拼接、字幕与响度；可选 Remotion 字幕路径有额外依赖。

## 对我们的意义与扩展方向

以下是本地研究判断，不是上游已实现的集成。

与 [LongHorizon-Harness](../003-longhorizon-harness/README.md) 研究互补：持续执行框架安排进度、反馈和续接，本库提供具体创作环节的输入输出及专业方法。接入时仍需保留创作选择与媒体生产的明确边界。

| 优先级 | 扩展 | 待验证价值 |
| :--- | :--- | :--- |
| 高 | 修改影响清单 | 人物、台词或镜头变化后标记受影响文档及素材，减少找漏 |
| 高 | 实际媒体质量检测 | 检查角色相似度、画面文字、黑帧、对白与声音，补足文档校验 |
| 高 | 按镜头统计生产成本 | 记录费用、耗时、重试原因和采用情况，以可用成片衡量收益 |
| 中 | 模型能力配置与回归 | 集中维护时长、参考方式、音画模式等差异 |
| 中 | 与持续执行框架结合 | 处理依赖、失败与已授权工作，实际生产形成单独的有边界任务 |
| 中 | 迁移内容领域 | 面向培训情景剧、产品演示、品牌故事重写方法与评估规则 |

下一步用原创、双角色、单场景、30—60 秒故事，对比直接创作与技能工作流的耗时、人工修改、遗漏及每个可用镜头成本。首版不编造实验结果。
