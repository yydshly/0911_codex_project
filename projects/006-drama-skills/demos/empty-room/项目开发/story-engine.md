# 《空房签收》故事引擎

关联技能：short-drama-develop。来源：[创作简报](creative-brief.md)。当前为本地模拟工作版，非已批准制作档案。

## 1. 戏剧承诺

焦点人物许川想查清为何自己的声音从无人居住的房里传出，并停止他人替自己制造“已送达”的事实。对方掌握录音与订单接收端，想继续收集样本、让他按惯例离开。

## 2. 压力回路

异常订单出现 → 许川按流程完成 → 对方利用其惯常话术与记录盖过现场事实 → 许川寻找能独立验证的证据 → 对方改变声源或下单者 → 许川必须引入共同见证，放弃独自快速解决。

每一轮改变证据与暴露范围，不重复“门里又叫了一次名字”。他可以离开危险现场，但离开本身不能撤销被冒用的声音和订单记录；这构成后续追查的动机，不把人困在楼道里。

## 3. 作者层事实与限制

- 空房里没有第二个许川；门内声音通过设备发出。故事没有时间穿越、鬼魂或预知能力。
- 操控者只能利用已掌握的录音、订单资料与现场设备所获信息，不能知道许川未表达的想法。
- 订单变化来自虚构接收端的操作权限，绝非“说一句话就能自动控制所有配送平台”。
- EP001 的同音色只能支持“声音听起来相同”；主动应答支持“有响应机制”。这两点都不足以当场证明操控者身份或技术原理。
- EP002 的空房与设备证据建立发声路径；EP003 通过物业共同见证与记录关联，让冒用行为停止，并保留线索交有关方面处理。不靠主角强行破门或违法读取他人设备得出谜底。

## 4. 人物行动与状态升级

| 阶段 | 原策略 | 新证据或阻力 | 可见改变 |
| :--- | :--- | :--- | :--- |
| EP001 | 按备注放餐就走 | 同音色、未操作签收、点名要求换人 | 收回未交付餐品，边退边录像 |
| EP002 | 带着录像寻找说话者 | 物业合法开门，空房中只有发声设备 | 放弃“另一个我在里面”的猜想，转查声音来源 |
| EP003 | 想独自抓现行 | 新配送人可能继续提供样本 | 与物业共同见证，把接收与送达事实公开核对 |

## 5. 铺垫与兑现

| ID | 首次载体 | 可支持的结论 | 后续兑现 |
| :--- | :--- | :--- | :--- |
| SET-VOICE | EP001 门内重复许川的送餐话术 | 相同音色出现在错误位置 | EP002 设备与历史录音解释声源 |
| SET-RECEIPT | EP001 手机签收状态改变 | 许川没有按键，状态却变了 | EP003 核对虚构接收端记录，解释谁控制状态 |
| SET-NAME | EP001 结尾喊出许川姓名 | 对方知道他的姓名 | EP002 订单资料与采样对象相连；不能仅靠姓名证明摄像头存在 |

## 6. 连续性与精确交接

首集到第二集：许川在走廊退离 1204，左手提原封餐袋，右手持正在录像的黑壳手机；门未打开。他已录下结尾点名语音，未承诺取得之前全部对话录音。第二集以他向物业展示这段结尾录像开始，不凭空多出全程素材。

## 7. 终止条件

当送达与接收由可共同核对的事实记录，幕后者无法再靠单方声音替许川确认交付，旧回路结束。最后一次由真实许川对真实收件人说“您的外卖到了”，让普通话术恢复原本用途。最终身份调查保留为后续程序，不冒充首集已经破案。
