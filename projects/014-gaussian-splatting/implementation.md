研究对象为 graphdeco-inria/gaussian-splatting，固定提交见 [来源记录](notes.md)。本章依据官方文档、论文和源码，不代表已在本机训练该原库。

## 能力、输入与输出

| 环节 | 输入 | 输出与能力 |
| --- | --- | --- |
| 数据准备 | 同一静态场景的重叠照片；视频需先抽帧 | COLMAP 相机、位姿、稀疏点云和去畸变图像 |
| 场景训练 | 图像、已知相机、初始点；可选深度等 | 针对该场景优化的三维高斯 |
| 模型保存 | 高斯属性、训练设置 | 高斯 PLY、设置；按选项保存训练检查点 |
| 离线渲染 | 训练模型和数据相机 | 对应视角的渲染图像 |
| 交互查看 | 已训练模型 | SIBR 桌面新视角实时观看；另有训练进程查看器 |
| 评估 | 留出视角及真实图像 | PSNR、SSIM、LPIPS 等图像质量结果 |

PLY 只是容器格式：普通点云 PLY、三角网格 PLY、高斯 PLY 的属性可能不同。高斯文件能否在其他软件正确显示，取决于尺度、不透明度、球谐等属性的约定与支持程度。[原库 README](https://github.com/graphdeco-inria/gaussian-splatting)

## 1. 从相机定位建立初始场景

`convert.py` 调用 COLMAP 做特征提取、匹配、映射与去畸变。真实场景通常从 SfM 稀疏点初始化高斯；相机参数在进入训练前需要可靠。

稀疏点不是最终成品，作用是给优化一个空间起点。训练主体通过改变高斯来拟合观测，并不自动替代 COLMAP 的完整相机标定工作。默认数据加载期望已去畸变、支持的针孔相机模型；NeRF Synthetic 数据另有加载路径。

## 2. 高斯保存哪些参数

| 参数 | 数学或代码含义 | 直观作用 |
| --- | --- | --- |
| 中心 μ | 三维坐标 | 放在哪里 |
| 尺度 s | 三个方向的伸展 | 是细长、扁平还是近似球形 |
| 旋转 q | 归一化四元数 | 朝什么方向伸展 |
| 不透明度 α | 经 sigmoid 等变换约束 | 对后方内容遮挡多少 |
| 球谐系数 SH | 根据视线方向计算颜色 | 拟合随观看方向变化的外观 |

高斯的空间权重可写为：

```text
G(x) = exp[-1/2 · (x-μ)ᵀ Σ⁻¹ (x-μ)]
Σ = R S Sᵀ Rᵀ
```

用尺度和旋转构造协方差，比直接任意修改矩阵更容易保持其有效性。各方向可以不同，称为“各向异性”。球谐让颜色随方向变化，但它没有自动把光源、材质、反射与阴影物理解耦。[场景模型源码](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f7834b564019656c3e3fcc3646292f727d/scene/gaussian_model.py)

## 3. 可微渲染把图像误差传回三维

每轮选择一个训练相机，渲染当前高斯，计算它和真实照片的差异，然后反向传播。基础图像损失组合像素 L1 与结构相似性项：

```text
L = (1-λ) · L1(image, reference) + λ · (1-SSIM(image, reference))
```

当提供有效深度时，当前实现还可增加逆深度差异项。优化器更新位置、尺度、旋转、SH、不透明度等参数；曝光参数有对应优化处理。这里的梯度是数值信号，不是模型口头说“把椅腿变细”。[训练源码](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f7834b564019656c3e3fcc3646292f727d/train.py)

## 4. 为什么需要增密、拆分与裁剪

开始的稀疏高斯不足以表达全部细节。代码累积屏幕空间位置梯度，用梯度和尺度等条件选择候选高斯：小尺度候选可以复制，大尺度候选可以拆分为更小高斯；几乎透明或尺寸过大的高斯可以移除。周期性不透明度重置帮助后续优化与清理。

这是控制表示容量的一种启发式策略，并不等同“识别出一个物体，再为这个物体建模”。高斯通常没有天然的“鞋带”“桌腿”标签。Splat.js、Postshot 等采用的 MCMC 式迁移／增长策略也不等于逐行复用原版增密算法。[增密代码](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f7834b564019656c3e3fcc3646292f727d/scene/gaussian_model.py)

## 5. 渲染为什么快

三维高斯经相机变换和局部投影近似形成二维椭圆。渲染器剔除不可见候选，把屏幕划分为小块，组织与每块相交的高斯并排序，再进行前向透明混合。

```text
某像素颜色 C = Σᵢ [ cᵢ · aᵢ · Πⱼ<ᵢ(1-aⱼ) ]
```

这里的 `aᵢ` 包含该像素处二维高斯权重与学习到的不透明度，前面的高斯降低后方贡献。它是高效的近似可见性处理，并非完整物理光线追踪；排序与投影近似也会导致特定视角下的伪影。CUDA 执行大量并行操作；训练还需要反向计算。[渲染接口](https://github.com/graphdeco-inria/gaussian-splatting/blob/54c035f7834b564019656c3e3fcc3646292f727d/gaussian_renderer/__init__.py)、[光栅器](https://github.com/graphdeco-inria/diff-gaussian-rasterization)

## 当前可选增强与边界

| 增强 | 解决什么问题 | 使用条件与限制 |
| --- | --- | --- |
| 加速光栅器与优化器 | 减少训练时间 | 需要按官方说明安装对应实现；速度取决于配置，行为可能与原始版本不同 |
| 深度正则 | 约束弱纹理区域、减少部分漂浮物 | 要准备深度与尺度对齐；不同场景可能收益小或变差 |
| 曝光补偿 | 处理不同照片的曝光差异 | 通过图像仿射颜色变换等拟合；不等于任意重光照 |
| 抗锯齿 | 改善尺度变化时的闪烁与锯齿 | 按训练及查看配置启用；不应把部分滤波集成等同全部 Mip-Splatting 方法 |
| SIBR 俯视图 | 检查相机与初始点云关系 | 辅助观察，不是新增重建算法 |
| OpenXR | VR 查看 | 有指定分支与依赖，不能假定默认安装即具备 |

上述均以 [官方当前使用说明](https://github.com/graphdeco-inria/gaussian-splatting)为依据。原库没有开箱即用的动态人体、骨骼、物体语义编辑、完整网格提取或浏览器重建产品。

## 准备条件与运行路径

官方训练流程依赖 NVIDIA CUDA GPU、Python/PyTorch、C++ 编译环境和 CUDA 扩展。README 给出论文评估质量的 24 GB 显存配置；较小显存可调整图像设备、分辨率或增密策略，但可能影响速度或质量。论文级配置不是所有场景的最低门槛。

Windows／Linux 的编译器、PyTorch CUDA 运行时和本机 CUDA 工具链应匹配。仓库含子模块；安装应依据固定提交的环境与 README，而不是无条件升级依赖。本次只提供研究网页，不安装 GPU 训练环境。

```text
准备照片 → COLMAP 数据处理 → train.py 场景训练
→ render.py 渲染 → metrics.py 评估 → SIBR 查看
```

## 与 Splat.js 的关系

| 项目 | 官方 Gaussian Splatting | Splat.js |
| --- | --- | --- |
| 共同点 | 使用可优化三维高斯拟合多视角照片 | 使用可优化三维高斯拟合多视角照片 |
| 运行 | PyTorch、CUDA 与桌面查看器 | JavaScript 与 WebGPU 等浏览器技术 |
| 空间求解 | 通常外部 COLMAP | 自有浏览器 SfM 流程 |
| 训练策略 | 原版增密，另有可选增强 | 含 MCMC 式迁移增长等自身策略 |
| 定位 | 原始算法参考实现 | 面向浏览器的完整重建流程 |
| 本机证据 | 本轮未训练 | 旧任务鞋子与 Truck 已实测 |

不能凭“一个用 CUDA、一个在网页”就给画质排名；需要同输入、同留出集与同等资源比较。Splat.js 也不是把照片按角度贴在一起：观看时使用的是已求解的空间表示。[Splat.js](https://github.com/arrival-space/splat.js)
