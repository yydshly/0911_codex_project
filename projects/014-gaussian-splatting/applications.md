# 应用、扩展与验证计划

[返回总览](understanding.md) · [同类产品](comparison.md)

本章为基于技术能力的应用判断与待实现方向，不是官方原库已有业务功能，也不是本轮已完成的产品验证。

## 适用场景与需要补齐的能力

| 场景 | 可复用的技术价值 | 产品层还需要什么 |
| --- | --- | --- |
| 商品外观展示 | 实拍重建后从不同角度查看材质与外观 | 商品资料、热点、加载优化、背景清理、跨设备测试 |
| 房产／展厅／酒店导览 | 记录真实空间外观，提供新视角观看 | 路线、房间连接、讲解、移动限制、权限与分享 |
| 文物／建筑视觉留档 | 保存多视角外观与采集证据 | 时间与来源记录、版本、长期格式与媒体授权 |
| 影视／游戏采集 | 快速获得真实场景外观用于预览与背景 | 引擎集成、碰撞代理、物体分离、材质与光照策略 |
| 数字孪生可视化 | 真实环境的视觉底图 | 设备身份、尺度与坐标、实时数据、告警和维护流程 |
| 几何资产与测量 | 网格路线或混合路线恢复表面 | 独立尺寸校验、拓扑修复、精度报告、CAD 适配 |

静态、高覆盖、清晰、多视角数据更有利。动态人物、反光透明、白墙、反复纹理、极近特写和远景混合、缺失背面都可能影响结果。高斯渲染逼真不能替代测量精度报告。

## 具体扩展方向

| 扩展 | 实现思路 | 可参考公开项目／验证点 |
| --- | --- | --- |
| 网页与移动端 | 浏览器渲染、裁剪、压缩、分块与按需加载 | [Splat.js](https://github.com/arrival-space/splat.js)、[SuperSplat](https://github.com/playcanvas/supersplat)；验证首屏、显存、触控与视角一致性 |
| 大场景 | 分区训练、全局对齐、构建层级、按视角选择细节 | [Hierarchical 3D Gaussians](https://github.com/graphdeco-inria/hierarchical-3d-gaussians)；注意接缝、曝光、尺度与资源管理 |
| 网格与可编辑资产 | 表面对齐正则、提取网格、网格与高斯绑定 | [SuGaR](https://github.com/Anttwo/SuGaR)；评估表面、薄结构与混合表示对齐 |
| 动态／4D | 引入时间、形变或时间相关高斯参数 | [4DGaussians](https://github.com/hustvl/4DGaussians)；需要动态数据与时间一致性评估 |
| 语义交互 | 将视觉／语言特征融合到场景表示 | [LangSplat](https://github.com/minghanqin/LangSplat)；验证定位、物体选取，不能把语言相关性等同物体真值 |
| 重光照与材质 | 恢复法线、材质、光源，增加物理约束与阴影处理 | 属于额外研究；原版 SH 颜色不自动提供可编辑物理材质 |
| 降本与实时性 | 调整高斯预算、剪枝、量化、球谐阶数和渲染细节 | 同时测画质、内存、文件体积和帧率；压缩可能产生损失 |
| 自动采集质量反馈 | 检查模糊、覆盖、匹配失败、曝光与重叠 | 提醒补拍而不是让用户反复盲目训练；仍需真场景验证 |

以上参考项目不是默认集成到本库的能力。引入时分别核查许可证、模型权重、依赖与数据条件。

## 建议首先验证的两个实验

**实验 A：同一只鞋，高斯与网格对照。**复用授权清晰的多视角数据，分别选择 Splat.js／官方高斯和摄影测量流程。对比外观、背面覆盖、鞋带薄结构、导出兼容、表面可编辑性与实际尺寸；不把两种输出的优点混成一个“质量分数”。

**实验 B：同一照片集，不同 3DGS 实现对照。**比较 Splat.js、Postshot、Brush 或官方库时，记录版本、硬件、分辨率、相机来源、高斯预算、训练步数或时间、抗锯齿和曝光开关。若比较端到端体验，要计入选帧与相机求解；若只比较训练器，应尽量使用相同的相机与初始数据。

## 怎样评估，才不会被演示误导

| 指标 | 测什么 | 常见误读 |
| --- | --- | --- |
| 留出视角 PSNR／SSIM／LPIPS | 没参与训练的真实照片与渲染的差异 | 用训练视角分数证明新视角泛化 |
| 几何误差与尺寸 | 与扫描真值或标尺对比 | 用高 PSNR 证明毫米精度 |
| 相机定位与覆盖 | 注册比例、重投影误差、失败区域 | 全部照片注册就认为模型无缺陷 |
| 性能 | 前处理、训练、峰值显存、加载、稳定帧率 | 只报纯训练时间，或不同分辨率横比 |
| 资产可用性 | 重载、材质、SH、坐标、网格、跨查看器 | 能导出 PLY 就认定任何软件都能正确读取 |
| 产品价值 | 用户是否更快理解商品／空间或完成任务 | 好看的演示自动证明商业需求 |

本轮没有重新跑算法实验；旧鞋子实验未留出测试集，因此它证明流程和交互可行，不足以给出算法间画质排名。

## 当前最可执行的下一步

先复用已验证鞋子场景完成一个轻量商品浏览任务，记录用户关心的角度、细节和加载体验。需要几何编辑或尺寸时再加入网格路线；需要静态空间时先补一个普通房间实测。人体动画、换装、任意重光照和城市规模应作为独立扩展，分别验证。
