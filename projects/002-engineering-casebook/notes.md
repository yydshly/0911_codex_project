## 目标与范围

在独立子项目中展示上游文章案例，并提供中文概括。对全部条目完成标题导读，对已阅读原文的案例给出更深入总结，始终保留来源与内容依据。

## 版本与环境

- 来源提交：`9ef9509126254406440c0e5ee09f609d0876418a`。
- 整理日期：2026-09-10。
- 环境：Windows、Node.js；纯静态前端，无第三方依赖与后端数据服务。

## 内容方法

1. 保存上游 README、MIT 许可证与引用图片。
2. 解析公司标题和编号文章行，保留标题、URL、主题、年份及公司内原始编号。
3. 为当前快照分配 001–343 的案例序号，并逐条编写中文标题导读。
4. 对已读取正文的文章整理问题、做法、结果、边界和研究启示，记录原文章节及核对日期。
5. 同时生成网页数据和 Markdown 中文目录，避免两份内容独立维护造成不一致。

“标题导读”只概括标题中明确的信息；详情中的阅读问题属于研究建议。“原文总结”基于实际阅读，文中报告的性能、费用等结果没有进行本地复现。

上游某些公司内编号不连续，例如 Swiggy 从 14 跳到 16；因此按实际条目计数而不以原编号最大值推算。案例序号仅在当前固定快照内稳定。脚本对快照做 SHA-256 校验，避免替换上游后把旧中文内容静默对应到新条目。

## 技术设计

数据在本地生成，前端只读取同目录静态脚本，避免打开本地 HTML 时受到跨域数据请求限制。搜索覆盖中文导读、英文标题、主题、公司及已总结内容；多个搜索词取交集，筛选条件叠加，再进行稳定排序与分页。

详情使用原生 dialog，动态内容经过 HTML 转义。预览服务仅绑定回环地址，只允许 GET 与 HEAD，并限制读取范围在静态目录。没有账号系统、远程写入、分析跟踪或外部运行依赖。
