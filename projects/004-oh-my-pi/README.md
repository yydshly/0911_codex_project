# 003 · oh-my-pi（OMP）

> **oh-my-pi 是基于 Pi 开源项目二次开发的 AI 编程 Agent 工具，定位类似 Codex CLI。它依靠接入的大模型理解需求、分析问题和生成代码，在 Pi 基础上完善代码编辑、语言服务、调试、执行环境和多代理协作，让模型能够在实际项目中执行“读代码 → 修改文件 → 运行检查 → 根据反馈继续修改”的工作流程。**

## 我们形成的核心理解

| 层次 | 负责什么 |
| :--- | :--- |
| 大模型 | 理解需求、分析问题、生成代码、决定下一步；通过外部服务或本地模型接入 |
| Pi | 提供编程代理运行、工具调用和会话等基础 |
| oh-my-pi | 基于 Pi 二次开发，完善工具、执行流程、反馈、协作和扩展能力 |

OMP 本身没有训练一个新模型。它依赖模型能力，并通过更好的工具和流程，让已有模型更充分、更可靠地发挥能力。这里的“更可靠”是设计目标，实际效果需要固定任务和环境进行评测。

“类似 Codex CLI”描述的是产品类别：接收自然语言任务，操作代码项目并反馈结果。OMP 的代码来源是 Pi；这个类比不表示 OMP 基于 Codex 开发，也不表示两者能力、权限机制或效果完全相同。

## 内部能力与研究重点

| 模块 | 具体能力 | 值得研究的问题 |
| :--- | :--- | :--- |
| 搜索与编辑 | 文件搜索、Hashline 快照与行号定位、AST 结构化查询和修改 | 工具接口如何减少定位错误、无效补丁与重复输出 |
| 语言服务与调试 | LSP 查询定义、引用、诊断与重命名；DAP 检查断点、调用栈和变量 | 如何把代码语义和运行证据交给模型，支持正确决策 |
| 执行环境 | 持久化 Shell、Python 内核、Bun JavaScript 环境、测试与后台任务 | 状态保留、输出管理、超时和取消如何协同工作 |
| 多代理协作 | 子任务、并发控制、可选工作区隔离、结构化结果和补丁交付 | 拆分任务后怎样收集证据、整合改动和处理失败 |
| 会话与记忆 | 历史压缩、恢复、可选项目记忆、Advisor 过程审查 | 如何避免丢失约束、使用过期经验或重复干扰 |
| 接入与扩展 | 多模型配置、MCP、自定义工具、浏览器、SDK / RPC | 如何适配我们的研究流程和外部系统 |

上述能力包含第三方技术集成及 Pi/OMP 代码，不应全部视为 OMP 原创；部分能力需启用配置或准备外部依赖。模块机制、源码入口和待验证问题详见[研究笔记](notes.md#内部模块与证据)。

## 对我们的意义

- 作为完整的编程代理样本，研究模型、工具、上下文和实际运行结果如何协作。
- 优先验证代码编辑、LSP / DAP、执行环境和多代理机制，再决定哪些设计可以复用。
- 后续可通过扩展或 SDK 接入我们的中文研究模板、版本与许可证记录、检查命令和验收标准。
- “自动生成符合本仓库规范的研究档案”是我们的候选扩展方向，不是上游已经内置的功能。
