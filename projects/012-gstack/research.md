# gstack：软件研发方法如何成为 Agent Skill

[项目介绍](README.md) · [57 项逐技能解读](skills.md) · [场景实验](notes.md)

## 核心理解

gstack 把成熟研发方法组织为结构化技能，由现有 Agent 根据目标和上下文执行。一个技能通常包含适用条件、事实来源、判断方法、步骤、工具、限制、完成检查与交接产物。不同技能主要改变工作组织方式，而非训练一套新模型。

底层模型负责理解需求、提出假设、追踪代码和判断结果；宿主提供会话与工具调用；程序实现浏览器控制、路径检查、日志、证据和模板生成。具体能力要逐项看源码和宿主支持。

固定研究提交 `71f6048e8ada25180e61438abc1d98cb151fe9a7`，日期 2026-09-10。上游 README 的角色数量是分类口径，本文按真实独立技能文件建立 57 项目录，不据此宣称所有宿主安装了 57 个命令。

## 能力与场景

| 环节 | 能力 | 适用场景 |
| --- | --- | --- |
| 需求与产品 | office-hours、产品评审、spec | 新功能、范围不清、形成可验收工作项 |
| 工程与体验 | 工程/设计/DX 规划、autoplan | 架构决策、开发者产品、实施前降低遗漏 |
| 设计实现 | 设计系统、多方案、HTML、图与 PDF | 视觉方向、页面和可编辑说明产物 |
| 代码与质量 | review、investigate、health、cso、benchmark | 变更检查、根因调查、质量与性能验证 |
| 浏览器 | browse、qa、qa-only、scrape、skillify | Web 流程测试、网页提取及可重用脚本 |
| 交付 | ship、setup-deploy、land-and-deploy、canary | PR 准备、部署、发布后有限观察 |
| 记忆与协作 | 上下文保存恢复、learn、GBrain、第二模型 | 长任务衔接、经验检索、独立意见 |
| 平台专项 | 保护 hook、宿主适配、iOS 技能 | 范围保护、新平台和真机测试 |

最适合具备代码、可运行环境和测试基础的迭代项目。小改动按需选技能。算法正确性、生产性能和业务价值仍需对应评测，浏览器 QA 或角色评分不能替代它们。

## 四个内部机制

### 1. 模板组织工作方法

`SKILL.md.tmpl` 描述领域步骤，公共 resolver 填入前置规则、浏览器协议和宿主差异，生成 `SKILL.md`。部分长章节分到 sections 后按需读取。宿主配置决定目录、元数据、名称替换及禁用的能力。

这种生成主要是文本与配置转换。自然语言中的循环、停止和问答通常由模型理解执行，不能因此认定有严格状态机。某些环节另有脚本、hook 或程序检查，需分开辨认。

### 2. 真实工具闭环

浏览器在支持环境下优先 Aside，否则使用自带 Chromium。自带路径通过 CLI → 本机 HTTP 服务 → Playwright → 页面操作，保留会话并减少重复启动。快照程序将可访问性树映射为引用和定位器，Agent 根据引用点击、截图或读取反馈。

因此 QA 能实际操作。选择什么路径、是否把现象判断为问题、如何修复仍依赖模型。截图存在不代表业务目标已满足。

### 3. 文件化交接与独立复核

需求输出设计文档，工程评审输出测试计划，QA 读取前序产物，交付引用审查和验证记录。部分审查调用新上下文 Agent 或另一模型，减少单次上下文偏差；这些调用需要宿主、程序和账户可用。

独立上下文不是绝对独立判断，同模型可能共享盲点。失效或未执行的检查不能报告为通过。

### 4. 可确定检查由代码完成

上游 `gstack-evidence` 将命令、退出结果、日志和工作树内容关联，判断记录是否仍适用当前文件。`careful` 与 `freeze` 在支持宿主中通过 hook 检查命令与编辑路径。前者不是完整系统沙箱，后者不自动拦截所有 shell 写入。

程序能确认命令和指纹，不知道测试是否覆盖全部业务。专业评审和确定性测试应各自承担能验证的部分。

## 对我们的意义

研究总仓库可以把“资料 → 假设 → 最小实验 → 实际验证 → 研究结论”固化为流程。优先借鉴可复用的检查方法与证据交接，并继续使用我们的编号、来源、许可证、截图和部署规范。

与 LongHorizon 的关系：gstack 细化每个研发环节如何做，LongHorizon 组织目标如何分轮推进和验收。可以研究外层安排任务、内层使用领域技能的组合；目前只是扩展方案，未验证现成接口或一键组合。

## 扩展方向

1. 中文研究技能：固定能力、原理、场景、意义、扩展与证据边界，记录版本和许可证。
2. 多项目规则：在真实构建和 CI 中核对去重、索引、目录、链接、图片性质与清单。
3. 证据关联：连接原始要求、测试、截图、提交与发布资源，区分结构完整和真实核验。
4. 回归沉淀：从浏览器发现转成可重复测试，保留失败输入与修复证据。
5. 长任务协作：与 LongHorizon 定义阶段输入输出、阻塞原因、重试范围和结束条件。
6. 实际评测：比较缺陷发现、误报、返工、耗时、模型成本和人工介入，再决定采用范围。

## 本次实践能证明什么

本地检查器按固定方法经过九阶段推进，21 项规则测试和 17 项浏览器检查通过，发现并修复一项真实边界缺陷。能够证明这个本地产物在记录范围内可用，方法带来了可核对的产物与反馈。

不能由此证明 gstack 全量原生安装可用、所有技能都执行过、多人协作成功、模型整体能力提升或生产部署成功。详细替换与限制见实验记录。
